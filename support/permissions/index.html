Permissions and installation.

Mynah is not from the App Store. macOS will ask you to approve it and grant two permissions. This page explains what to expect and how to fix common problems.

Install Mynah correctly

01

Download

Download Mynah only from mynah.site. Do not install from unofficial mirrors or unknown links.

02

Move to Applications

Open the DMG and drag Mynah.app into your Applications folder. Do not run it from Downloads, the Desktop, or the mounted DMG.

03

Launch and approve

Open Mynah from Applications. Approve the macOS security prompt, then grant Microphone and Accessibility when asked.

Why macOS shows a security prompt

Not from the App Store Mynah is distributed directly from mynah.site. macOS may ask you to confirm you want to open it the first time.
What to do If macOS blocks the app, open System Settings → Privacy & Security, scroll to the Mynah message, and click Open Anyway. Then launch Mynah again from Applications.
Is this safe? Yes. This prompt is normal for independently distributed Mac apps. Only approve it if you downloaded Mynah from mynah.site.

Permissions Mynah needs

Microphone Mynah captures your voice while you hold Fn. Without this, the app cannot record speech. Enable it in System Settings → Privacy & Security → Microphone.
Accessibility Mynah uses Accessibility to place your transcript into the active app at the cursor. Without this, Fn and paste will not work. Enable it in System Settings → Privacy & Security → Accessibility.
macOS controls these Mynah cannot grant itself permissions. macOS requires you to approve them. If a permission is missing, dictation or paste will silently fail.

Troubleshooting

Mynah won't open

Open System Settings → Privacy & Security and click Open Anyway next to the Mynah message. Then launch Mynah from Applications, not from Downloads or the DMG.

Fn key does nothing

Confirm Mynah is running (menu-bar icon visible). Check that both Microphone and Accessibility are enabled in System Settings. Quit and reopen Mynah from Applications. Test in TextEdit or Notes first.

Recording works but text doesn't paste

Confirm Accessibility permission is enabled. Click into a normal text field, then try again. Check that paste-at-cursor is enabled in Mynah settings. Restart Mynah if needed.

Mynah doesn't appear in the permission list

Quit Mynah. Open it from /Applications/Mynah.app. Trigger the action that needs the permission (e.g. hold Fn). Then return to System Settings — Mynah should now appear.

Accessibility looks enabled but still doesn't work

macOS can hold a stale entry from an older build. Quit Mynah. Remove any Mynah or SpeakPaste entries from System Settings → Accessibility. Add Mynah again from Applications. Enable it and restart Mynah. If it still fails, restart the Mac.

I previously used SpeakPaste

Mynah uses a new app identity (com.mynah.app). macOS treats it as a different app. Delete SpeakPaste.app and remove old SpeakPaste entries from Accessibility. Then install Mynah and approve permissions fresh.

Menu bar icon is gone after closing the window

Mynah is designed to stay running in the menu bar even when the main window is closed. If the menu-bar icon has disappeared, reopen Mynah from Applications.

Still not working

Quit Mynah. Restart the Mac. Open Mynah from Applications. Confirm both permissions are enabled. Test Fn in TextEdit. If the problem continues, contact irfan@teachmeai.in with a description of the issue.

About local diagnostics

Mynah can store local diagnostics to help troubleshoot setup, permissions, latency, and paste behavior. Diagnostics are kept on your Mac and describe app health — not the words you dictate.

What diagnostics includeApp version, permission state, trigger state, recording and transcription timing, paste success or failure, and local engine status.
What diagnostics never includeRaw audio, transcript text, clipboard content, or private content from other apps.
